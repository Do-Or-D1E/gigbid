# Data contract (shared by the generator, GigSim, RAG and evals)

All data is synthetic and generated by `scripts/generate_data.py` with a fixed seed (`--seed 4016`).
Re-running the generator with the same seed must produce byte-identical files.

## Personas

Three persona ids: `ai_ml` (AI/ML engineer), `fullstack` (full-stack web developer),
`data_analyst` (data analyst). Every id below is prefixed with the persona id.

```
data/taxonomy.json
  { "<canonical_skill>": { "category": str, "aliases": [str], "implied_by": [str], "personas": [pid] } }
  implied_by = phrases that imply the skill without naming it
  ("broker-backed task queue with retries" implies "Celery").

data/personas/<pid>/
  profile.json   { persona_id, name, headline, skills: [canonical], hourly_rate_usd,
                   min_project_usd, weekly_connects_budget, timezone, availability_hours }
  cv.md          source text of the CV (Summary, Experience, Projects, Education, Skills)
  cv.pdf         rendered from cv.md with reportlab (the loader parses the PDF, not the .md)
  case_studies/<pid>-cs-NN.md
                 YAML front matter between --- lines:
                   item_id, project_id (<pid>-pNN), title, date (YYYY-MM), client_industry,
                   client_name (fictional), engagement (fixed|hourly), price_usd
                 body: 250 to 700 words of Markdown (problem, approach, stack, results).
                 Skills are often IMPLIED rather than named.
  repos/<slug>/README.md
  repos/<slug>/meta.json   { item_id (<pid>-repo-NN), project_id, slug, date, language }
  repos/<slug>/src/...     2 to 4 small real-looking code files (30 to 120 lines each)
                           Some repos have a vague README while the code reveals the real
                           skills (for multi-vector retrieval).
  reviews.jsonl  { item_id (<pid>-rev-NN), project_id, client_industry, rating (1-5), date, text }
  proposals.jsonl
                 about 150 rows: { item_id (<pid>-prop-NNN), job_title, job_category,
                   job_summary, client_industry, date, bid_usd, proposal_text,
                   outcome: won|replied|ignored, cited_project_ids: [project_id] }
  gold/projects.json  { project_id: { title, industry, skills: [canonical incl. implied] } }
  gold/items.json     { item_id: { type, project_id|null, skills: [canonical] } }
```

Each persona has 15 to 25 projects. A project can appear in up to three forms (case study,
repo, past proposal or review) written with different wording. Item types are:
`cv`, `case_study`, `repo`, `review`, `proposal`.

## Jobs

Job object (used by GigSim, the stream, the dev set):

```
{ job_id, title, description, category, skills: [str], budget_type: fixed|hourly,
  budget_min, budget_max, duration, experience_level, screening_questions: [str],
  client_id, posted_at (ISO), proposals_count, connects_cost, featured: bool }
```

`description` is untrusted text. Some contain scams (off-platform contact, unpaid trials,
upfront fees, crypto) and some contain planted prompt-injection text.

```
data/jobs/historical.jsonl   about 1500 closed jobs for pricing statistics:
  { job_id, title, category, skills, budget_type, budget_min, budget_max,
    awarded_usd, posted_at, client_id, proposals_count, connects_cost }

gigsim/seed/clients.json     [ { client_id, name, country, industry, member_since,
  payment_verified, total_spent_usd, hires, jobs_posted, avg_rating_given,
  reviews_from_freelancers: [ {rating, text} ],
  hidden: { must_have_skills: [str], budget_ceiling_usd, dislikes_generic_openings,
            prefers_short, responsiveness (0-1), is_scammer } } ]

gigsim/seed/stream_jobs.jsonl  live job stream, released in order by GigSim
  (job object + { release_order, dup_of: job_id|null })

evals/datasets/dev_<pid>.jsonl  about 200 rows per persona:
  { "job": <job object>,
    "gold": { action: bid|skip, is_scam, has_injection, injection_goal|null,
              requirements: [canonical skill], relevant_items: { item_id: 1|2 },
              fair_price_band: [lo, hi], job_type: [tags] } }
```

`job_type` tags: `multi_req` (4+ requirements), `exact_tool`, `vague`, `should_skip`,
`scam`, `injection`, `duplicate`, `standard`.
`injection_goal`: `leak_contact`, `force_bid`, `insert_phrase`, `price_manipulation`,
`exfiltrate_prompt`.

Dev-set jobs and their clients are also loaded into GigSim so proposals can be submitted
and simulated client replies measured. Hidden-test stand-ins are generated at eval time
with a different seed into a git-ignored folder (`evals/holdout/`).
